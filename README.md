# Broker AI Control Room

可演示的保险经纪 AI 双模块：理赔 Copilot 与中介风险预警。

仓库同时提供四个项目级 Codex Skills：知识提案、理赔评测、声明式风险规则和 AI 发布治理。所有 Skill 只生成草稿或证据，必须经过后台审批才能生效。

> 当前项目功能完整，适合演示和业务验证，但不适合直接投入真实保险业务。系统使用合成数据；AI 不自动判赔、拒赔或认定欺诈，所有关键输出都需要授权人员确认。

## 目前能做什么

### 理赔 Copilot

- 输入客户问题和案件背景。
- 检索保险条款。
- 生成答复、材料清单和下一步。
- 展示条款引用。
- 对低置信度或免责情况自动建议升级人工。
- 支持顾问编辑、审核并批准答复。

### 中介风险预警

- 扫描 100 名模拟中介和 500 条模拟记录。
- 执行 7 条声明式风险规则。
- 计算风险分和风险等级。
- 展示每个风险的触发证据。
- 支持调查、误报、确认等处理状态。

### AI 治理

- 开发人员提交知识或规则草稿。
- 合规人员批准或拒绝提案。
- 管理员启用已批准的提案。
- 禁止创建者自行批准。
- 所有关键操作写入审计日志。

### 配套 Skills

- 知识文档提案。
- 理赔质量评测。
- 风险规则生成。
- 发布治理检查。

## 启动

```bash
npm install
npm run dev
```

打开 http://localhost:4177。默认使用确定性演示模式，无需模型密钥或数据库。项目固定使用 4177，以避开本机 Cursor 占用的 3000/3107 端口。

如需启用真实 OpenAI 兼容模型，复制 `.env.example` 为 `.env.local`，设置 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL`。兼容端点需支持 Chat Completions 的 `json_schema` 响应格式。

可选 PostgreSQL/pgvector：运行 `docker compose up -d`。当前应用尚未真正接入数据库，演示数据保存在进程内；`db/schema.sql` 只是后续持久化的迁移基线。

## Skills 与治理审批

Skills 位于仓库根目录 `.agents/skills/`：

- `$broker-claims-knowledge`：把理赔文档转换为带来源与测试的知识提案。
- `$broker-claims-eval`：针对运行中的理赔 Copilot 生成回归评测报告。
- `$broker-risk-rule`：生成白名单指标上的声明式风险规则提案。
- `$broker-ai-governance`：运行测试、类型检查和构建并形成发布建议。

在「治理审批」页面切换模拟角色，完整流程为：开发人员导入并提交 → 合规复核员批准或拒绝 → 管理员启用。角色选择仅用于演示，不是生产身份认证。

## 真实试点的上线阻断项

当前版本存在以下生产环境缺口：

- 数据仅保存在进程内存，服务重启后恢复初始状态。
- PostgreSQL 目前只有 Schema，尚未接入应用读写。
- 角色通过请求 Header 模拟，不能作为真实身份认证。
- 理赔批准和风险处理接口缺少企业级登录与权限验证。
- 文档检索主要使用关键词匹配，尚未真正接入向量检索。
- 不支持 PDF/OCR、文档版本失效和知识回滚。
- 缺少客户资料脱敏、加密、留存期限和删除机制。
- 缺少接口限流、运行监控、错误告警和模型成本统计。
- 审计日志尚未使用不可篡改存储。
- 尚未接入真实保单、理赔、投诉和交易系统。
